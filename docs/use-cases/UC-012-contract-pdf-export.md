## 2. Summary

From the contract detail page, the owner can download the contract as a **professional bilingual (Arabic + English) PDF**. The PDF is generated server-side using **DomPDF** (already in the stack from `UC-003` receipt) and streamed directly as a download — no file is stored on disk. The PDF includes the full contract: project details, client info, milestone table with tax breakdown, terms and conditions, and the digital acceptance record (signed-at timestamp + client IP) if the contract has been signed.

---

### Primary actor

Authenticated freelancer or small business owner (contract owner only).

### Secondary actors

- **System:** Laravel MVC; DomPDF

### Preconditions

- [ ] A `contracts` row exists owned by the authenticated user
- [ ] DomPDF is installed (`barryvdh/laravel-dompdf`)

### Postconditions (success)

- [ ] A PDF file is streamed as a download to the browser
- [ ] No file is written to the server disk

### Postconditions (failure — if applicable)

- [ ] If DomPDF rendering fails, the user sees a flash error and remains on the contract page

## 5. User journey (happy path)

### 5.1 Trigger

1. Owner is on `GET /contracts/{id}` (contract detail page).
2. Clicks **"Export PDF"** button.
3. Browser navigates to `GET /contracts/{id}/pdf` (standard HTTP GET, not Inertia).
4. Middleware checks: authenticated + `contracts.user_id = auth()->id()`.

### 5.2 PDF generation

Controller loads the full contract with milestones, then renders a **Blade view** (not Inertia — DomPDF uses Blade for HTML-to-PDF conversion):

**PDF content (top to bottom):**

1. **Header:** Financial OS logo + "Project Contract" label
2. **Parties:** Freelancer display name ↔ Client name
3. **Project info:** name, description, start/end dates
4. **Financial summary:**
   - Subtotal (sum of milestones)
   - Tax (`tax_rate`% = `tax_amount`) — row hidden if `tax_rate = 0`
   - **Grand total**
5. **Milestones table:** Name · % · Pre-tax amount · Tax amount · Total · Due date · Status
6. **Terms and conditions:** full text
7. **Digital acceptance record** (if `status = active` or `completed`):
   - *"Digitally accepted by [client_name] on [signed_at] (IP: [client_ip])"*
   - If not yet signed: *"Pending client acceptance"*
8. **Footer:** *"Generated by Financial OS · [timestamp]"*

**Bilingual approach for MVP:** Generate the PDF in **English only** first. Arabic RTL in DomPDF requires additional font configuration (`mPDF` or custom Arabic font loading). If time allows, add Arabic headers alongside English. Mark this as a Day 4 stretch goal.

### 5.3 Stream response

```php
return PDF::loadView('contracts.pdf', $data)
    ->download("contract-{$contract->project_name}-{$contract->id}.pdf");
```

## 8. Mock and assumption box (hackathon)

- **English-only PDF for MVP:** Full bilingual (Arabic RTL) is a stretch goal for Day 4. English PDF is sufficient for demo.
- **No disk storage:** Stream directly — avoids S3/MinIO setup for this feature.

## 9. Acceptance criteria (testable)

- [ ] Given an authenticated contract owner, when they click "Export PDF", then a PDF download begins
- [ ] Given the downloaded PDF, then it contains project name, client name, milestones table, terms, and financial summary with tax breakdown
- [ ] Given a signed contract, then the PDF includes the acceptance record (signed_at + client_ip)
- [ ] Given an unsigned contract, then the PDF shows "Pending client acceptance"
- [ ] Given another user's contract ID, then `403` is returned

## 10. Scope boundaries

### In scope

- Server-side PDF generation with DomPDF, streamed as download
- Full contract content including tax breakdown and digital acceptance record
- English language for MVP

### Out of scope

- Storing PDF on disk or S3 (stream-only for MVP)
- Full Arabic RTL rendering (Day 4 stretch)
- Client-side PDF download from the public contract review page (post-MVP)
